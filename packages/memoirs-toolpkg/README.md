# Volume of Memoirs / 记忆之书

一个独立的 Operit ToolPkg。它只读访问 `com.claude_capability_pack.memory` 的本地 Markdown 记忆库，每天生成一本临时页码不同的《记忆之书》。

## 已实现

- 只读扫描 `memory/buckets/**/*.md`，不修改原记忆。
- 同时读取记忆插件维护的 bucket cache，并兼容当前目录、嵌套旧目录与早期独立配置目录。
- 按当前聊天与角色作用域筛选记忆。
- 可跟随当前聊天，也可固定绑定一个聊天窗口；成书、角色盲选和角色批注统一使用绑定窗口。
- 排除归档、过短内容、精确重复正文，并可配置是否排除 `resolved` / `digested`。
- 每日成书与稳定的当日页码映射；次日重新洗牌。
- 独立阅读历史与冷却期，避免近期反复读到同一条记忆。
- Reiko 与当前聊天角色分别盲选页码；双方选定前，界面不会收到页面映射。
- 当前角色选择通过当前 chat、当前 character card 发起，并设置 `persist_turn: false` 与 `hide_user_message: true`。
- 双方选到同一页时只展示一次，同时保留双方选择记录。
- 用户与当前角色的短批注分层保存在本插件目录，不回写原记忆。
- “今天不读”后当日不再进入阅读流程。
- “今日书册 / 阅读记录”双页导航；阅读记录按实际翻阅事件保存日期、双方页码、记忆和当时批注。
- 共读完成后生成一次性的共享事件；只在固定绑定窗口的下一条真实用户消息进入模型时临时带回，并在回复成功持久化后消费。
- “回到对话”只切换到固定窗口，不伪造用户消息，也不向聊天历史写入隐藏技术轮次。
- 可安装 Operit 工作流，每 15 分钟检查一次冷场条件；它只安排一次邀请时机，角色仍可结合下一条真实消息自行决定是否邀请。

## 当前边界

- 在当前公开 API 下，工作流不能凭空生成一条完全无伪历史的角色消息。因此自动邀请会等到固定窗口的下一条真实用户消息，再交由角色自然决定是否提出邀请。
- ToolPkg 没有公开的跨插件 IPC 包选择参数，因此本插件直接读取记忆插件配置目录；正常情况下优先单次读取记忆插件的完整缓存，缓存不可用时才回退到 Markdown 扫描。
- 当前角色的盲选与批注会产生一次真实模型请求，但不会保存为普通聊天轮次。模型供应商仍可能计费。
- 待同步事件使用 `pending -> in_flight -> consumed` 状态。模型请求失败或取消时不会提前丢失；租约过期后可以在下一次真实请求中重试。

## 本插件数据

插件状态保存在：

`ToolPkg.getConfigDir("com.volumeofmemoirs.operit")/memoirs/state.json`

其中包含每日书册映射、阅读历史、事件状态、批注、设置和最近聊天活动时间。原始记忆正文不会复制进状态文件。
